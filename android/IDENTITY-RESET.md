# 重新安装后登录与身份更新

用户名统一为 2–32 位汉字、小写字母、数字、下划线。卸载或清空数据后，原账号密码可用于重新登录；新安装没有原聊天历史。服务器端七天未在线导致的销户是另一种情形，已销户账号仍需重新注册。

Android 登录发现本机私钥与服务器公钥不匹配时，先把候选新身份及其预密钥原子保存到原 SecureVault，再调用 `POST /api/keys/reset`，携带当前登录令牌、再次验证的密码和仅含公钥的 bundle。服务端更新 accountId，旧令牌失效；客户端采用返回的新令牌。普通公钥 PUT 仍不能更换身份。

候选状态在网络请求前保存；密码验证失败或网络失败不会替换原身份或删除本地历史。若服务器已更新但最终本地写入未完成，下次登录发现服务器公钥与候选相符，会采用已保存的候选私钥，避免再次生成无法匹配的身份。所有候选、原私钥材料和历史均留在现有 AES-GCM / AndroidKeyStore 安全存储，没有明文备份。

联系人收到 `identity_reset` 证明时，只有旧 accountId 和旧公钥与本地绑定匹配才更新。对应会话、旧安全码核对状态和待发密文会撤销；原已解密历史保留，联系人保留，也不会被标为已销户。证明中的新公钥立即锁定，随后服务器查询不能换成未获证明的另一公钥或 accountId。必须重新核对新的安全码后才能发送。重复证明、迟到的旧证明不会清除新会话或新核对状态。

发送帧带 `toAccountId`，服务器可拒绝发送过程中目标已更新身份的旧密文。新登录的 WebSocket 回调受控制器 generation 隔离；事件接口由服务端按当前 JWT accountId 隔离，兼容有 `recipientAccountId` 的事件时客户端也检查该字段。

本轮在 Windows JVM 上使用真实 libsignal 运行身份更新测试，覆盖双向新会话、无证明变化拒绝、重新核对要求、重复及迟到证明、旧收件事件隔离、候选保存重试与不公开私钥。原 Java↔Node 互通测试也运行。没有安装或测试手机；KeyStore 与完整登录网络交互不能用 JVM 测试代替设备验证。
