# Chat Android

原生 Android 客户端，与本项目 Windows 客户端共用 Java 服务器和 Signal 消息格式。最低 Android 8.0（API 26）。本轮交付开发测试 APK，不是应用商店正式发行版。

当前源码为 Android 0.4.9（versionCode 15）。会话列表、聊天输入框右侧“＋”及语音、视频、发送位置、共享位置四个入口可用；前台通话服务按系统版本设置相应类型。已验证功能与尚未通过的设备检查见[Android 验证范围](VALIDATION.md)。

## USB 安装与测试

1. 先按[根目录说明](../README.md)构建服务器 0.2.3，再从仓库根目录在另一个 PowerShell 窗口运行 `java -jar .\server\target\chat-server-0.2.3.jar`，默认地址 `http://127.0.0.1:8082`。如果服务器已经运行，不要重复启动。
2. 手机开启开发者选项和 USB 调试，使用可传数据的 USB 线连接电脑；解锁手机并允许这台电脑调试。
3. 已在本目录构建 APK 时可运行 `install-usb.cmd`。脚本检查设备、安装 APK、转发端口并打开应用；也可按下方命令手动安装。需要 Android SDK 的 platform-tools，并设置 `ANDROID_HOME`。
4. 手机服务器地址填写 `http://127.0.0.1:8082`。USB 转发使手机的这个端口连接到电脑服务器。不要填写电脑磁盘路径。拔掉 USB 或重启后需重新运行端口转发。
   首次打开应用会先要求添加服务器。以后在“设置”中添加、切换或移除服务器；切换后只显示该服务器的账号和联系人。
5. 在手机注册账号，例如 `ab`、`phone_alice` 或 `小明`，或使用原账号密码登录。用户名支持 2–32 位汉字、小写字母、数字、下划线，英文名也可为 2 位。账号仅支持一个有效设备身份：原私钥丢失或使用不同安装登录时，会再次验证密码并更新设备身份，旧设备凭证失效，双方需重新核对安全码。
6. Windows 客户端登录自己的账号，双方输入对方用户名。查看并通过可信渠道核对安全码，确认后发送文字，检查双方消息正文与接收状态。
   手机首页有“消息”“联系人”“设置”三个入口。点右上角“＋”添加联系人，已有账号再次登录时点选用户名并输入密码即可。切换服务器会退出当前登录，再选择该服务器的账号。
7. 离线测试：退出接收方，另一端发送；接收方重新登录应收到离线密文并解密。聊天内容在服务器以密文保存，服务器仍知道账号、收发双方、时间等元数据；本地私钥和会话留在各自设备。
8. 删除联系人后，双方的聊天许可都会撤销，旧消息仍可在原会话中查看。任一方再次发消息时只能先发一条，接收方同意后才能继续聊天。
9. 服务器按账号最近一次成功建立的加密通信连接计时；连续七天未连接将自动删除该账号在服务器上的密码记录、公钥、联系人关系，以及它参与的服务器密文消息。重新打开应用后要看到“在线”才算完成连接。本地已保存的历史不会因服务器清理而自动删除，但服务器无法恢复已删除的账号资料或密文。相关联系人会在在线通知或下次重连时移除，原会话显示“该用户已销户”，不能继续向旧账号发送消息。若对方重新注册同名账号，请从右上角“＋”重新打开会话，并重新核对安全码；旧身份的待发消息不会自动发给新账号。
10. 与联系人互相接受后，打开会话并点击发送按钮右侧的“＋”，可以选择语音或视频通话。首次使用按系统提示允许麦克风或摄像头。连接中和通话中显示完整界面，可最小化为可拖动的小窗；语音为圆角正方形，视频为真正裁切画面的圆角长方形。应用仍在后台运行且保持在线时可收到来电通知，接通后使用前台服务；应用被系统停止时没有离线来电推送。公网通话需要服务器正确配置 STUN/TURN，详见根目录《语音与视频通话》。

手动安装命令（在 `android/` 目录执行；若构建产物名称不同，先修改 `$apk`）：

```powershell
$adb = Join-Path $env:ANDROID_HOME 'platform-tools\adb.exe'
$apk = '.\app\build\outputs\apk\debug\app-arm64-v8a-debug.apk'
if (!(Test-Path -LiteralPath $apk)) { throw '未找到 APK，请先构建或检查成品目录' }
& $adb devices
& $adb install -r $apk
& $adb reverse tcp:8082 tcp:8082
& $adb shell am start -n com.example.chatandroid.debug/com.example.chatandroid.MainActivity
```

如果设备显示 `unauthorized`，在手机屏幕接受调试授权；没有设备时检查数据线、USB 驱动和 USB 调试设置。安装脚本不会清空应用数据。

## 构建

需要 JDK 21（当前 libsignal Java 库要求；服务器仍使用 JDK 17）、Android SDK platform 35、build-tools 35.0.0、Node.js，以及已安装依赖的 `../client`（仅互通测试需要 Node）。Gradle Wrapper 固定到 8.11.1 并校验官方发布的 SHA-256。

在 `android/` 目录配置 JDK 和 Android SDK 后运行 Gradle；`build-local.cmd` 可用于已有相应本地工具配置的 Windows 环境。

```powershell
$env:JAVA_HOME='C:\path\to\jdk-21'
$env:ANDROID_HOME='C:\path\to\android-sdk'
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

APK 在 `app/build/outputs/apk/debug/app-<处理器架构>-debug.apk`；选择与设备处理器架构对应的 APK。互通测试使用真实 Java 与 Node libsignal 原生库，不模拟加密。

## 当前范围

- 文字一对一聊天、注册登录、JWT、密文存储和 ACK、安全码、离线重连与本地会话恢复。首页显示联系人；多服务器地址和账号入口保存在本机并按服务器隔离，不保存密码。
- 一对一语音和视频通话；接通后离开聊天页不会立即挂断。通话媒体走 WebRTC DTLS-SRTP，临时信令不写入本地聊天历史或服务器消息库。信令未使用 Signal 加密或绑定安全码，服务器仍可看到 SDP、ICE 和通话元数据。
- AndroidKeyStore 保护本地私钥与已解密聊天历史；服务器仍保存账号、密码校验信息、公钥与密文。卸载应用或清空数据会删除本机私钥和聊天历史，但原账号仍可凭正确密码重新登录，以新设备身份继续聊天。更新身份会清除该账号参与的服务器旧密文；其他设备已有的本地历史仍保留，但不会恢复到新安装。若本机安全存储仍存在，身份更新保留该存储中已有的历史；损坏或缺失其 KeyStore 密钥时拒绝覆盖。应用备份已禁用。
- 暂无离线来电推送、群聊、图片和多设备登录。Android 可能停止后台应用；回到应用后重连并领取离线消息。
- USB 本机连接允许 HTTP。远程部署使用 HTTPS；开发构建的局域网 HTTP 测试开关不会提供账号凭据的传输保护。
- 消息加密调用官方 libsignal，不自行设计密码协议；本项目不是 Signal 官方客户端，也不连接 Signal 服务。

## 聊天位置与记录查找

聊天输入框右侧“＋”展开同一行四个入口：语音通话、视频通话、发送位置、共享位置。右上角“⋮”菜单提供“查找聊天记录”。位置支持单次发送、前台实时共享、停止和一小时超时；发送方和接收方都能从位置卡片选择地图应用或浏览器打开坐标。本地历史支持文字及日期筛选、分页与跳回原消息。定位权限只在主动选择位置功能时申请。详见[使用说明](../位置与聊天记录查找.md)与[验证范围](VALIDATION.md)。

更新已有 APK 时必须使用同一个签名密钥，否则 Android 会拒绝覆盖。build-local.cmd 优先沿用本机的 debug.keystore；也可通过 CHAT_ANDROID_DEBUG_KEYSTORE 指定仓库外的原密钥。不要将密钥提交到 Git，不要为了覆盖更新而卸载正式客户端。


## 本地存储、会话续期与后台提醒（2026-10-01）

- 本地协议状态与消息历史分别加密；消息按记录保存于 SQLite，同一完整同步事务提交 Signal 状态与消息变更。日常收发不再复制或重新加密全历史，总历史不再受原 vault 的 16 MiB 上限限制；单加密记录仍有 16 MiB 的异常尺寸保护。
- 首次登录读取已有 `.vault`，在发布密钥或发送消息前迁入新数据库，把旧文件无损移至 `.migrated` 备份，旧版代码不会自动读取它们。数据库检查点存在时只读取数据库；任何密文校验、密钥、历史计数或数据库读取错误均拒绝覆盖。保存失败会回滚本次内存变更并暂停加解密，需重新登录。请勿降级为只读取旧 vault 的客户端，也不要把 `.migrated` 改回 `.vault`；备份只保存迁移时刻的旧 ratchet 状态。新客户端发现备份存在但数据库检查点缺失时会停止，而不会回退旧密钥状态；迁移后降级不会保留当前历史/会话。
- 支持新版服务器的短期 JWT 与轮换续期凭据，凭据仅在内存中。通常在到期前五分钟续期，短有效期则在剩余期的一半续期；成功后在原 WebSocket 完成重新认证，保留正在进行的通话。注销、服务器切换或关闭取消续期；失败有界重试，旧服务器无续期凭据时保留原登录规则。
- 已存活的 WebSocket 收到并安全保存新消息后，后台显示联系人与“收到新消息，点击查看”，不显示正文；锁屏公共版本只显示“Chat 新消息”。会话列表显示未读条数，打开会话清除未读。需允许系统通知。未加入推送服务或常驻同步服务，系统停止进程后不会推送；再次打开并登录、恢复在线后领取服务器保留的密文。
- 本版显式处理方向、屏幕大小、字号、显示密度、界面模式、语言和布局方向变化，重绘页面并保留当前 controller、登录与通话对象。未声明的其他配置变化、进程被系统杀死、重启手机仍会结束内存会话，随后需要重新登录。这不改变单设备规则。
- USB 安装脚本优先本次构建的对应 ABI APK，缺失时从 `outputs/Chat-v版本/` 的最高数值版本查找对应 APK；也可传入 `-Version 0.5.9` 指定成品目录。调试签名需继续使用原调试 keystore。
